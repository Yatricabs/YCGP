# Gradle Wrapper Notes

## Project status

The Android project is configured for Gradle 8.12 and contains the standard wrapper entry points:

- `android/gradlew` for Linux/macOS/CI
- `android/gradlew.bat` for Windows
- `android/gradle/wrapper/gradle-wrapper.properties`

The official Gradle Wrapper JAR is a binary generated by the Gradle `wrapper` task. The packaging environment used for this archive did not have a Gradle distribution installed and could not retrieve binary artifacts from the internet, so the official JAR is not fabricated or substituted here.

## CI behavior

GitHub Actions installs Gradle 8.12 using `gradle/actions/setup-gradle`, then runs:

```text
gradle wrapper --gradle-version 8.12 --distribution-type bin
```

This generates the official `gradle-wrapper.jar` in the CI workspace before the build, after which CI executes:

```text
./gradlew :app:assembleRelease --no-daemon --stacktrace --console=plain
```

This keeps the build pinned to the version declared by the repository and uses the standard Gradle Wrapper entry point.

## Expected source-tree wrapper layout

```text
android/
  gradlew
  gradlew.bat
  gradle/
    wrapper/
      gradle-wrapper.jar
      gradle-wrapper.jar.sha256
      gradle-wrapper.properties
```

Before a developer commits the generated JAR from a machine with Gradle installed, the repository's CI workflow can generate it automatically.

## GitHub web-upload executable bit

When `android/gradlew` is added or replaced through GitHub's web upload UI, the file can arrive in the repository without its POSIX executable mode. GitHub Actions therefore runs `chmod +x android/gradlew` before `./gradlew --version` and the release build. This does not change the script contents; it only restores the required executable permission on the CI runner.


## CI ordering correction (v42)

GitHub's web upload can store `android/gradlew` without the executable bit. The workflow therefore must not execute `./gradlew` before `chmod +x android/gradlew`. The initial environment check uses the runner-installed `gradle --version`; wrapper generation and permission restoration happen before any `./gradlew` invocation.
